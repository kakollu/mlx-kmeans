k-means on one Apple M5 Max laptop · exact, not approximate

Three problems that
used to need a cluster

98 million taxi trips, 96 million satellite pixels, a million OpenAI embeddings. Each one clustered here in under 13 seconds, using every row — no sampling, no Spark, no cloud bill. The algorithm is ordinary k-means; what changed is that a laptop now holds the whole dataset in memory and reads it at 400 GB/s.

Case 1 · Demand segmentation

98.5M NYC taxi trips → eight trip archetypes

Every yellow-cab trip from January to August 2015, clustered on fare, distance, duration, hour, tip rate and party size — the segmentation an operations team would actually run.

Two segments are an artifact

Two of the eight differ mainly by tip rate: ~23% versus ~1%. That is not generosity, it is card versus cash — the meter only records a tip when the fare is paid by card. A third of all trips split on how people paid, not how they travelled.

The fix is a judgement call, not a model tweak: cluster card trips only, or drop tip rate and treat tipping as its own question.

Case 2 · Unsupervised land cover

96M satellite pixels → land cover without labels

One cloud-free Sentinel-2 scene over New York, 10-metre resolution, clustered on four bands plus vegetation and water indices. No training set: the classes come from what the pixels look like.

Case 3 · Vector search

1M OpenAI embeddings → themes, and the index itself

Embeddings of a million Wikipedia/DBpedia entities, 1,536 dimensions each. Clustered twice: a small k to see what the corpus is about, and a large k because that is how a vector index is built — every IVF index in a RAG stack starts with k-means over the embeddings.

Each line: share of the corpus, then the entities closest to that cluster's centre. Nobody labelled these — the topics are what the embedding space already encodes.

The evidence

Faster, and the same answer

Time for one k-means pass against the fastest public library that reaches the same clustering quality on this machine — scikit-learn, FAISS, and a PyTorch-on-Metal implementation.

Run it yourself

On any Apple Silicon Mac

pip install mlx-kmeans

from mlx_kmeans import KMeans
model = KMeans(n_clusters=8).fit(X)      # X: (rows, dims) float32
model.cluster_centers_, model.labels_, model.inertia_

A MacBook Air has roughly a quarter of this machine's GPU, so expect roughly a quarter of the speed and a lower memory ceiling — still 100M+ rows at low dimensions. quick_bench.py prints what your own Mac does.

Data: NYC TLC yellow-taxi records (Jan–Aug 2015); Sentinel-2 L2A scene via AWS Open Data; DBpedia entity embeddings (OpenAI text-embedding-ada-002) via Hugging Face.
All timings measured on one Apple M5 Max (40 GPU cores, 128 GB unified memory). Benchmarks, the correctness suite and these demo scripts are in the repository.
